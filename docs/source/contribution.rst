Как контрибьютить
=================

Правила простые: любые доработки идут через ветку и PR в ``main``.

Разработческое окружение
------------------------

.. code-block:: bash

   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements-dev.txt
   python manage.py bootstrap
   python manage.py runserver

Стиль кода
----------

* Форматирование Python — ``black`` (по-умолчанию) + ``ruff`` для линтинга,
  если у вас установлены. CI-хуков нет, но перед PR прогоните локально:

  .. code-block:: bash

     python -m compileall apps config desktop
     python manage.py check

* Русские тексты интерфейса живут прямо в шаблонах — отдельного i18n нет.

Работа с моделями
-----------------

* Миграции создаются командой ``python manage.py makemigrations`` и
  коммитятся в ветку. Файлы миграций — это API, их нельзя удалять или
  переименовывать без backfill-скрипта.
* Бизнес-логика — не во ``views`` и не в ``models``, а в ``services.py``.
  Views должны быть тонкими: получить объект, вызвать сервис, отдать шаблон.

Шаблоны
-------

* Общая раскладка в ``templates/base.html``, топ-бар в
  ``templates/partials/topbar.html``.
* HTMX-фрагменты называем с префиксом подчёркивания, например
  ``pos/_order_panel.html`` — так ясно, что это не полная страница.

Документация
------------

Изменили API/модель — обновите ``docs/source/*.rst`` и убедитесь, что
``make html`` из ``docs/`` собирается без предупреждений.

.. code-block:: bash

   cd docs
   make html

HTML появляется в ``docs/build/html/index.html``.

Тесты
-----

Пакет тестов пока минимальный; всё, что вы напишите, будет к месту.

.. code-block:: bash

   python manage.py test

PR-чеклист
----------

1. Ветка называется ``cursor/<короткое-описание>-add6`` или
   ``feature/<название>``.
2. Есть краткий summary в описании PR — какая проблема, что сделано, как
   проверить.
3. ``python manage.py check`` не ругается, ``make html`` в ``docs/``
   собирается, вручную проверен основной сценарий: заказ → оплата → выдача
   → закрытие дня.
4. Никаких секретов и локальных ``*.sqlite3`` в коммитах.
