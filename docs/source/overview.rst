Обзор продукта
==============

CashMachine — рабочее место кассира кофейни. Всё стоит и работает локально
на ноутбуке или мини-ПК за кассой: Django-приложение поднимает SQLite,
рендерит HTMX-интерфейс в браузере (или в окне pywebview на Windows) и не
требует внешнего сервера.

Ключевые сценарии
-----------------

* **Оформление заказа.** На экране «Касса» три колонки: очередь, меню и
  текущий чек. Рядом с вкладками тегов есть поле «Поиск»: оно оставляет
  плитки, в названии которых есть набранная подстрока, внутри текущей
  вкладки. Очистка поля возвращает полный список вкладки. Товар без допов
  по-прежнему добавляется одним нажатием. Товар с допами
  открывает шторку: группы одного выбора уже стоят на варианте по
  умолчанию, группы нескольких — пустые. Цена строки пересчитывается сразу.
  Имя гостя предзаполнено, комментарий и «С собой» правятся на месте.
  Зелёная кнопка «Оплачено» отмечает чек оплаченным и отправляет его баристе.
* **Очередь.** Левая колонка кассы показывает имя, состав с допами,
  комментарий и время на часах смены: оплата и выдача (статус
  «Готово»). Те же часы стоят в панели открытого заказа. Готовность
  и оплата — разные оси. «В очередь» оставляет
  заказ неоплаченным: на карточке маркер 💸 (подпись «не оплачено»)
  и красная обводка со всех сторон. «Оплатить» этот маркер не показывает.
  Тап по плашке статуса циклит «Не готово → Готово → Отменено» и оплату
  не меняет. Правый клик по карточке открывает то же меню готовности
  и ставит статус сразу.
  У каждой позиции есть галочка «отдали»: отмеченная строка зачёркнута
  и полупрозрачна. Галочка не открывает редактор. Если отмечены все
  позиции и заказ оплачен, через 5 секунд он сам становится «Готово»
  (пишется время выдачи). Снятие галочки или оплаты в эти 5 секунд
  отменяет перевод.
  Заголовок «Очередь» — это список из трёх очередей текущей смены:
  «Очередь» (активные), «Готовые» и «Отмена». Карточки в каждой идут
  по времени создания, старые сверху. Оплаченное «Готово» — любым
  способом, в том числе автопереводом — ещё 13 секунд остаётся в
  основной очереди, чтобы статус можно было поправить кликом или
  правой кнопкой, затем плавно уходит и дальше видно только в
  «Готовые». «Отменено» уходит в «Отмена» с той же паузой 13 секунд.
  Неоплаченное «Готово» из основной очереди не уходит: его ещё нужно
  оплатить. Оплата такого заказа запускает те же 13 секунд.
  Тап по самой карточке открывает заказ справа. Если в правой колонке
  был черновик с позициями, он сам уходит в очередь неоплаченным.
* **Вход.** Отдельной формы пароля для кассы нет: анонимная сессия
  становится пользователем ``admin`` с доступом к кассе, смене,
  статистике и меню.
* **Смена.** На ``/pos/shift/`` кассир сам вписывает бизнес-дату,
  время начала (по умолчанию 19:30, поле обязательное) и имя
  «Кассир» (оно попадает в шапку). Абсолютные часы ноутбука в дату
  и начало не подставляются. ``opened_at`` пишется только как ноль
  отсчёта: время заказа — это начало плюс прошедшее с открытия.
  ``closed_at`` по-прежнему пустой. Пока смены нет, не открывается
  только «Касса». «Меню» и «Статистика» работают и без открытой смены.
  Закрытие двухшаговое: сводка, затем
  точное слово ``ЗАКРЫТЬ``. Заказы в статусе «не готово» не
  отменяются автоматически и не блокируют закрытие — они остаются
  в истории этой смены.
* **Меню.** Менеджер (`admin`) в ``/catalog/`` правит позиции без
  Django-админки и без открытой смены: слева фильтр по тегам, в центре список, справа карточка
  (название, цена, видимость, тег, группы допов). Справочники групп допов
  и тегов — ``/catalog/groups/`` и ``/catalog/tags/``. У группы есть режим
  одного или нескольких вариантов, флаг обязательности и опции с ценой и
  значением по умолчанию. Кассир получает 403. Следующая загрузка кассы
  уже показывает правки.
* **Статистика.** ``/pos/stats/`` открывается и без смены и группирует заказы по
  :attr:`apps.orders.models.Shift.business_date`: эта смена, последние
  7 или 30 смен, всё время или диапазон дат. «Выдано» — статус «Готово»
  (и «Отдан» со старого экрана выдачи). Выручка — оплаченные и не
  отменённые заказы, вместе с допами. На странице два графика той же
  выборки: сумма по дате смены и нагрузка по времени смены (заказы
  за 30 или 60 минут, по времени оплаты). Выгрузка CSV считает ту же
  выборку и добавляет колонки времени оплаты и выдачи.
* **Старый дневной снимок.** ``/analytics/close-day/`` по-прежнему пишет
  :class:`apps.analytics.models.DailySummary` по календарной дате. Это не
  закрытие смены на кассе.

Роли
----

* ``admin`` — полный доступ: касса, выдача, «Меню» (in-app CRUD),
  аналитика. Суперпользователи вдобавок видят Django-админку.
* ``cashier`` — касса, смена и статистика. Вкладка «Меню» видна, но
  ``/catalog/`` отвечает 403: править меню может только администратор.
  Без открытой смены на экран открытия уводит только касса.
  Статистика и редактор меню открываются как обычно.

UX-принципы
-----------

* Никаких лишних кликов: товар без допов добавляется в заказ ровно
  одним нажатием, товар с допами — шторка с уже выбранными дефолтами.
* Активная строка в панели заказа подсвечивается для страховки от
  «случайного минуса».
* Формат «В зале / С собой» — крупные чипы вместо выпадающего списка.
* Экран выдачи автоматически обновляется каждые 5 секунд через HTMX polling,
  чтобы бариста и кассир видели одинаковую очередь.

Технологический стек
--------------------

* **Backend:** Python 3.10+, Django 5.x, SQLite, django-htmx, WhiteNoise.
* **Frontend:** серверный рендер + HTMX для интерактивности + Alpine.js
  (18 KiB, только для мелких клиентских тумблеров).
* **Desktop:** pywebview (окно) + PyInstaller (сборка одного `.exe`).
* **Docs:** Sphinx с темой Furo, автогенерация из docstring через
  ``sphinx.ext.autodoc``.
